Relationships

Relationships connect tables together using matching fields. This eliminates data redundancy, ensures data integrity, and allows you to query across multiple tables.

Types of Relationships

One-to-Many (1:N)

The most common type. A single record in Table A can relate to many records in Table B, but each record in Table B relates to only one record in Table A.

Customer (One)
→
Orders (Many)

Example Tables:

Customers Table

CustomerID Name City
1 Andi Pratama Jakarta
2 Siti Nurhaliza Bandung

Orders Table

OrderID CustomerID (FK) Product Amount
101 1 Laptop Rp 12.000.000
102 1 Mouse Rp 250.000
103 2 Keyboard Rp 500.000

↑ Customer 1 (Andi) has 2 orders. Customer 2 (Siti) has 1 order. Each order belongs to exactly one customer.

Many-to-Many (M:N)

A record in Table A can relate to many records in Table B, and vice-versa. This requires a Junction Table (a third table that holds the foreign keys of both tables).

Student
→
Enrollments (Junction)
→
Class

Example Tables:

Students

StudentID Name
1 Andi
2 Budi

Enrollments (Junction)

StudentID ClassID
1 101
1 102
2 101

Classes

ClassID ClassName
101 Database
102 Web Dev

↑ Andi takes 2 classes (Database, Web Dev). The Database class has 2 students (Andi, Budi).

One-to-One (1:1)

Each record in Table A relates to exactly one record in Table B. Less common — typically used to split sensitive or rarely-used data.

Employee
→
Salary Details

Example Tables:

Employees

EmployeeID Name Department
1 Dewi Lestari IT
2 Rudi Hartono Finance

SalaryDetails

EmployeeID (FK) BaseSalary Bonus
1 Rp 15.000.000 Rp 2.000.000
2 Rp 12.000.000 Rp 1.500.000

↑ Each employee has exactly one salary record (kept separate for confidentiality).

Referential Integrity

Referential Integrity is a set of rules that Access enforces to ensure that relationships between records in related tables are valid. When enforced:

  • You cannot add a record to a related table if no matching record exists in the primary table. (e.g., You cannot create an Order for a Customer that doesn't exist.)
  • You cannot delete a record from the primary table if matching records exist in a related table. (e.g., You cannot delete a Customer who still has Orders.)
  • You cannot change a primary key value in the primary table if that record has related records.

Example

With Referential Integrity enforced on Customers → Orders:

  • Blocked: Adding an Order with CustomerID = 99 when no Customer with ID 99 exists.
  • Blocked: Deleting Customer "Andi" (ID=1) while he still has 2 orders.
  • Allowed: Adding an Order with CustomerID = 1 because Customer ID 1 exists.

To enforce Referential Integrity, check the "Enforce Referential Integrity" checkbox in the Edit Relationships dialog when creating or editing a relationship.

Cascade Update Related Fields

When Cascade Update is enabled, if you change the value of the primary key in the primary table, Access will automatically update all matching foreign key values in the related table.

Example

Before: Customer "Andi" has CustomerID = 1, and he has 2 orders both referencing CustomerID = 1.

Action: You change Andi's CustomerID from 1 to 100.

Result with Cascade Update ON: Both orders automatically update to CustomerID = 100.

Result with Cascade Update OFF: The change is blocked because it would orphan the orders.

Cascade Delete Related Records

When Cascade Delete is enabled, if you delete a record from the primary table, Access will automatically delete all matching records in the related table.

Example

Action: You delete Customer "Andi" (ID=1) from the Customers table.

Result with Cascade Delete ON: All of Andi's orders (OrderID 101 and 102) are automatically deleted.

Result with Cascade Delete OFF: The delete is blocked because Andi still has orders.

⚠ Caution: Use Cascade Delete carefully! Deleting a record in the primary table can result in the loss of many related records. Always back up your data first.
