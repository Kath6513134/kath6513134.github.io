Tables

Tables are the foundation of any Access database. They store all of your data in a structured format of rows (records) and columns (fields).

Records & Fields

Records (Rows)

Each row represents a single entry or item. For example, one customer, one product, or one transaction.

Fields (Columns)

Each column represents a specific piece of information about that item. For example: First Name, Last Name, Email, Phone Number.

Primary Key

A Primary Key is a field (or combination of fields) that uniquely identifies each record in a table. It prevents duplicate entries. Typically, an ID field with the AutoNumber data type is used.

Example: Students Table

StudentID (PK) FirstName LastName Email Major GPA
1 Andi Pratama andi@email.com Computer Science 3.85
2 Siti Nurhaliza siti@email.com Information Systems 3.72
3 Budi Santoso budi@email.com Computer Science 3.50
4 Dewi Lestari dewi@email.com Data Science 3.91

↑ Each row is one student (record). Each column is a field. StudentID is the Primary Key (AutoNumber).

Design View

Design View is where you define the structure of your table — not the data itself. Here you specify:

Field Name

The label for each column (e.g., FirstName, OrderDate, Price).

Data Type

What kind of data the field will hold (Short Text, Number, Date/Time, Currency, Yes/No, AutoNumber, etc.).

Description

An optional note to explain what this field is for. Appears in the status bar when the user is in that field.

Example: Students Table in Design View

Field Name Data Type Description
🔑 StudentID AutoNumber Primary Key, auto-generated
FirstName Short Text Student's first name
LastName Short Text Student's last name
Email Short Text Student's email address
Major Short Text Study program
GPA Number (Double) Grade Point Average (0.00 – 4.00)
EnrollmentDate Date/Time Date the student enrolled
IsActive Yes/No Currently enrolled?

Common Data Types

Short TextAlphanumeric characters, up to 255 characters. Names, titles, etc.
Long TextLonger text or combinations of text and numbers. Memos, descriptions.
NumberNumeric data for mathematical calculations.
Date/TimeDate and time values.
CurrencyMonetary values. Prevents rounding errors in calculations.
AutoNumberAutomatically generates a unique sequential number. Ideal for Primary Keys.
Yes/NoBoolean values (True/False, On/Off).
OLE ObjectEmbedded objects like images, audio, or documents.
HyperlinkWeb addresses or links to files.
AttachmentAttach files (images, documents) directly to a record.
Lookup WizardCreates a dropdown list that pulls values from another table or a fixed list.

Field Properties

In Design View, the bottom panel shows Field Properties for the selected field. These control data validation and formatting.

Example: Properties for GPA Field

Property Value Explanation
Field Size Double Allows decimal numbers
Format Fixed Shows as 3.85, not 3.8500001
Decimal Places 2 Always shows 2 decimal digits
Caption Grade Point Average Label shown in forms/reports
Default Value 0 New records start with GPA = 0
Validation Rule >=0 And <=4 Must be between 0 and 4
Validation Text GPA must be between 0.00 and 4.00 Error message if rule is violated
Required Yes Cannot be left blank

All Field Properties

Field SizeMaximum number of characters (for Text) or numeric range (for Number).
FormatControls how data is displayed (e.g., Short Date, Currency, Percent).
Input MaskA template that forces a specific format during data entry (e.g., phone number: (999) 000-0000).
CaptionA label shown instead of the field name in forms and reports.
Default ValueA value automatically entered when a new record is created.
Validation RuleAn expression that restricts what data can be entered (e.g., >=0 for positive numbers).
Validation TextError message shown when the Validation Rule is violated.
RequiredIf set to Yes, the field cannot be left blank.
IndexedSpeeds up searches and sorting on this field. Can enforce uniqueness.
